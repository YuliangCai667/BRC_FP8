# V1 FP4 格式迁移

准确继承 V1 `1dd21cb8b420f32c3c3bc33d8a0cd8f11a86ce6d`。
只扩展在线残差计算打包与 SM120 CUTLASS 模板实例：NVFP4 使用
`nv_float4_t<float_e2m1_t>`（E4M3/16 与 FP32 tensor scale）；MXFP4 使用
`mx_float4_t<float_e2m1_t>`（E8M0/32）。两者均使用真实 block-scaled Tensor Core
kernel 和 FP32 epilogue；E2M1 每 byte 两个 nibble，scale 沿 reduction 方向生成。
CARRY、Adam、LAG、双项 VJP、target 路由及训练协议完全继承 V1。

E2M1 使用 RTN/ties-to-even；RHT、随机舍入和 2D weight scaling 关闭。
NVFP4 local E4M3 scale 使用 optimization_barrier，确保 JIT 下归一化真正读取舍入后的
scale。否则会与独立打包产生约10.9%的乘法差异。MXFP4 用 E8M0 NaN scale 保留
无效输入，避免 E2M1 将 NaN 静默编码为零。

原生 oracle 使用同次 JIT 返回的实际 packed 操作数，反量化后的对照乘法显式
`Precision.HIGHEST`。默认 TF32 对照会自身引入约2.6e-4误差，不能判为后端错误。
实际 native/oracle 最大相对L2：NVFP4 `5.48e-7`，MXFP4 为0；覆盖
1024×4096×4096、4096×1024×4096、小batch、carry活性、小梯度及NaN传播。
两格式 Nsight trace 均记录5次声明格式的 SM120 block-scaled GEMM。
8项CPU编码/VJP/checkpoint测试通过；NVFP4 7项GPU编码及native检查分阶段完成。

MXFP4完整smoke通过16次learner updates、四任务各1episode和save/load下一步复现，
最大状态差异`1.82e-12`，allocator peak约6.40GiB。首次smoke的更新已通过，但诊断
闭包嵌入全权重常量造成OOM；修正诊断为运行时传入模型buffer后通过，未改训练算法。
诊断现在计算分布式Q的期望值对action的梯度，而非logit总和。
NVFP4同样通过16次真实更新、四任务评估和恢复检查；最大状态差异
`1.82e-12`，allocator peak `6852699904` bytes。详细证据见仓库外启动报告。
