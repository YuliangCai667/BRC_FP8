# Hybrid CARRY critic and actor FP8 deployment

## Motivation

The MXFP8 runs have not established a return advantage over the validated
per-tensor FP8 recipe. Restore that recipe as the baseline and isolate reading
the CARRY term in compute, then use the verified operator in the actor.

## Changes

- `legacy` remains the original main-only E4M3 forward / E5M2 backward.
  `hybrid` reads `s*(C+R/16)` using two E4M3 forward products, two E5M2×E4M3
  input-gradient products, and one physical FP32 weight gradient. Activations
  use current tensor amax; gradients retain Flax's delayed tensor amax rule.
  Both terms share the activation/gradient codes and update gradient metadata
  once. No MXFP8 block scales or native extension are used by this path.
- Online CARRY, target LAG, and block128/gain16 CARRY-Adam remain unchanged.
  Actor body selects `hybrid_main_plus_carry`; actor gradient scale/history
  are updated independently of critic metadata and survive checkpoint restore.
- Actor boundaries remain BF16 parameters with FP8 weight QAT. At 450k all
  actor Dense layers switch to the shared single-code W8A16 export path without
  resetting CARRY or Adam. Inactive hybrid gradient history is preserved.
  Final checkpoint export, package-only validation, and deployment evaluation
  remain automatic at 500k; the loader never needs a critic network.
- Entrypoints: `bash scripts/run_hybrid_critic.sh legacy` for the FP32-actor
  baseline, `bash scripts/run_hybrid_critic.sh hybrid` for the isolated critic,
  and `bash scripts/run_actor_qat_fp8_export.sh` for both hybrid bodies plus QAT.
  The actor launcher defaults to GPU1; `BRC_GPU_UUID` selects another authorized
  device. Each launch creates an independent run in the existing W&B project.

- Five GPU operator tests pass, covering zero carry equivalence to legacy,
  FP32 NumPy algebra on quantized operands, carry contributions to forward and
  input gradients, one weight gradient, metadata, batch1 and 1024×4096×4096.
  CPU algebra tests pass (full GPU shapes skipped). Compiled HLO contains two
  E4M3 Triton products and three FP8 cuBLAS backward products using E5M2.
- 51 existing FP8/optimizer/checkpoint CPU tests and 10 actor tests pass;
  an additional focused resume check passes after extending format rejection.
- Legacy and hybrid each complete 16 full-width learner updates on exactly
  the same 256×4 environment transitions and batch sampling sequence. Both
  complete four-task smoke evaluation and restore the next update exactly.
  Critic optimizer state is 572,066,388 bytes for both. Illustrative warmed
  update medians are 51.50/57.47 ms; these shared-GPU short tests are not a
  throughput benchmark. Whole-smoke allocator peaks are 5,893,509,120 /
  5,960,288,768 bytes, including compilation/diagnostics/recovery.

  unchanged delayed-scale history, and training-normalized `sum(Q)/1024`,
  legacy/hybrid Q relative errors against their FP32 effective-weight
  references are 0.0436%/0.0403%; action-gradient cosine is 0.9844/0.9871,
  relative L2 is 17.74%/16.01%, and norm ratio is 1.0089/0.9964. This is a
  local numerical probe, not a return comparison or gradient accuracy guarantee.
- Actor main and export-aligned phases each complete 16 full-width updates.
  Restore errors are 0 / 9.095e-13 in physical FP32 state; FP8/BF16 payloads
  restore exactly. Both body gradient histories become nonzero and persist

  Fresh paired four-task evaluation (one episode/task for this smoke) also

- The smoke package has five single-code FP8 Dense kernels: 216,064 code bytes

  persistent parameters total 253,104 bytes; Dense-only compression is 3.55×
  versus FP32. This package validates the pipeline and is not a trained model.

## Operational limits

The installed XLA/cuBLAS combination selects an invalid algorithm for some large
FP8 GEMMs with default autotuning. The launchers use
`--xla_gpu_autotune_level=0`, validated for both legacy and hybrid. Small Dense
dimensions are padded to 16 and cropped after GEMM. Record CUDA/XLA settings
when comparing throughput. No content/checkpoint hashes are generated by this
validation or the hybrid launch path.

Short tests do not establish long-horizon RL stability. Seed42 remains a new
500k experiment with a fixed 450k alignment boundary, not a continuation of an
MXFP8 optimizer trajectory. The actor's export codec remains E4M3 plus FP32
block32 scales (1.125 bytes/weight before padding), separate from the per-tensor
hybrid training compute. Final return and deployment quality remain pending
until the formal run and its final export/evaluation finish.
